1. What Is Sliding Window?

Sliding Window is an optimization technique for contiguous sequences on linear data structures (arrays, strings, lists). Instead of recomputing the result for every possible subarray with nested loops, a "window" defined by two pointers moves across the data — adding elements on the right and removing them on the left.

Complexity gain:

Brute Force Sliding Window
O(n²) or O(n³) O(n)

Every element enters the window once and leaves once → ≈ 2n operations.

2. How to Identify a Sliding Window Problem

Work through these three checks in order:

① Is the data structure linear? Array, string, or list. If yes, continue.

② Are contiguous elements involved? Look for keywords: subarray, substring, consecutive, continuous, window, segment. If yes, continue.

③ Is there an optimization or counting goal? Look for keywords: longest, shortest, maximum, minimum, sum, average, count, distinct, exactly K, at most K, contains. If yes → Sliding Window is very likely the right approach.

3. How It Works

State:  [  ← i (left)  ········  j (right) →  ]

1. Expand:  absorb arr[j] into the window
2. Validate: check the window condition
3. Shrink:  while invalid, remove arr[i] and advance i
4. Record:  update answer (max, min, count, …)
5. Repeat:  advance j until end of array

4. The Five Window Types

4.1 Fixed-Size Window

When to use: The window size k is given and never changes.

Recognition keywords: "subarray of size K", "window size K", "K consecutive elements", "fixed-length substring"

Idea: As j advances, add arr[j]; once the window reaches size k, record the answer, then remove arr[i] and slide forward.

Template:

int i = 0, j = 0;

while (j < n) {
    // 1. Include arr[j]
    add(arr[j]);

    if (j - i + 1 < k) {
        j++;
    } else { // window == k
        // 2. Process answer
        process();

        // 3. Slide: remove leftmost element
        remove(arr[i]);
        i++;
        j++;
    }
}

Example — Maximum Sum Subarray of Size K:

int maxSum(vector<int>& arr, int k) {
    int i = 0, j = 0, sum = 0, ans = INT_MIN;

    while (j < arr.size()) {
        sum += arr[j];

        if (j - i + 1 == k) {
            ans = max(ans, sum);
            sum -= arr[i++];
        }
        j++;
    }
    return ans;
}

  • Maximum Average Subarray I
  • Find All Anagrams in a String
  • Maximum Vowels in Substring of Length K
  • K Radius Subarray Averages

4.2 Variable — Longest Window

When to use: Find the maximum-length window satisfying a condition.

Recognition keywords: longest, maximum length, at most K

Idea: Expand aggressively. Shrink only when the condition breaks. Record window size after each shrink.

Template:

int i = 0, ans = 0;

for (int j = 0; j < n; j++) {
    add(arr[j]);                     // expand

    while (invalid()) {              // shrink until valid
        remove(arr[i++]);
    }

    ans = max(ans, j - i + 1);       // record longest valid window
}

Key problems and their conditions:

Problem Validity Condition
Longest Substring Without Repeating Characters no duplicate in window
Fruit Into Baskets at most 2 distinct elements
Longest Repeating Character Replacement windowSize - maxFreq <= k
Max Consecutive Ones III at most k zeros allowed

4.3 Variable — Shortest Window

When to use: Find the minimum-length window satisfying a condition.

Recognition keywords: minimum, shortest, smallest

Idea: Expand until the condition is met. Then shrink as aggressively as possible, recording the answer while the window is still valid.

Template:

int i = 0, ans = INT_MAX;

for (int j = 0; j < n; j++) {
    add(arr[j]);                     // expand

    while (valid()) {                // shrink while still valid
        ans = min(ans, j - i + 1);  // record inside the shrink loop
        remove(arr[i++]);
    }
}

⚠️ Key difference from Longest: The answer is recorded inside the while (valid) loop, not after it.

Practice problems:

  • Minimum Window Substring
  • Minimum Size Subarray Sum
  • Minimum Consecutive Cards to Pick Up

4.4 HashMap / Frequency Map Window

When to use: The condition depends on frequencies, duplicates, or distinct counts inside the window.

Common data structures: unordered_map, vector<int> freq[256]

Template:

unordered_map<char, int> freq;
int i = 0, ans = 0;

for (int j = 0; j < n; j++) {
    freq[s[j]]++;                          // expand

    while (invalid(freq)) {                // shrink
        freq[s[i]]--;
        if (freq[s[i]] == 0) freq.erase(s[i]);
        i++;
    }

    ans = max(ans, j - i + 1);            // or += (j - i + 1) for counting
}

Practice problems:

  • Longest Substring Without Repeating Characters
  • Longest Substring with At Most K Distinct Characters
  • Minimum Window Substring
  • Permutation in String
  • Longest Repeating Character Replacement

4.5 Monotonic Deque Window

When to use: You need the maximum or minimum element of every window of size k.

Data structure: deque<int> storing indices in monotonically decreasing (for max) or increasing (for min) order.

Key insight: Elements that can never be the answer are discarded immediately, keeping the deque lean. The front always holds the index of the current window's max (or min).

Template — Sliding Window Maximum:

vector<int> maxSlidingWindow(vector<int>& nums, int k) {
    deque<int> dq;   // stores indices; front = max of current window
    vector<int> ans;

    for (int i = 0; i < nums.size(); i++) {
        // Remove indices that have fallen out of the window
        while (!dq.empty() && dq.front() <= i - k)
            dq.pop_front();

        // Remove indices whose values are < current (they can never be the max)
        while (!dq.empty() && nums[dq.back()] < nums[i])
            dq.pop_back();

        dq.push_back(i);

        if (i >= k - 1)
            ans.push_back(nums[dq.front()]);
    }
    return ans;
}

Practice problems:

  • Sliding Window Maximum
  • Longest Continuous Subarray With Absolute Diff ≤ Limit

5. The "Exactly K" Trick

Problems asking for exactly K distinct elements (or sum, or odd numbers) are difficult to solve directly with a single sliding window, because shrinking becomes ambiguous.

The formula:

Exactly(K)  =  AtMost(K)  −  AtMost(K − 1)

Why it works:

AtMost(K)   counts subarrays with 0, 1, 2, …, K distinct elements
AtMost(K-1) counts subarrays with 0, 1, 2, …, K-1 distinct elements
Difference  = subarrays with exactly K distinct elements  ✓

Implement AtMost(x) using the Counting template (Section 4.2 / 4.3 variant), then call it twice.

Problems that use this trick:

  • Subarrays with K Different Integers
  • Count Number of Nice Subarrays
  • Binary Subarray Sum

6. Quick-Reference: Which Type to Use?

Situation Pattern
Window size is given as K Fixed Window
Longest sequence satisfying a condition Variable — Longest
Shortest sequence satisfying a condition Variable — Shortest
Condition involves frequencies or distinct counts HashMap Window
Need max/min of every window Monotonic Deque
Count subarrays with at most K Counting (record j - i + 1)
Count subarrays with exactly K AtMost(K) − AtMost(K−1)
Window defined by a second string Two-String Window (HashMap)

Counting subarrays: When a window [i…j] is valid, every subarray ending at j and starting anywhere from i to j is also valid — giving (j - i + 1) new valid subarrays to add to the answer.

7. Common Mistakes

① Forgetting to undo left element on shrink When i moves right, you must reverse whatever you did when that element entered: decrement its frequency, subtract from sum, etc.

② Infinite loops Every iteration must advance either i or j (or both). If neither moves, the loop is infinite.

③ Wrong validity condition A classic example: for Longest Repeating Character Replacement, the condition is:

window_size - maxFreq <= k    ✓

not maxFreq <= k ✗

④ Recording the answer at the wrong time

Goal When to record
Longest After the inner shrink loop
Shortest Inside the inner shrink loop (while still valid)
Counting After the inner shrink loop: ans += (j - i + 1)

8. Complexity

For almost all sliding window problems:

Complexity
Time O(n) — each pointer moves at most n times
Space O(1) for sum/pointer problems; O(k) or O(alphabet) for HashMap variants
